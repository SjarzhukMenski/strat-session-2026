## 4. Модель ролей и прав

- **Зритель** — любой анонимный пользователь; публичные страницы только для чтения.
- **Координатор** — создаёт проекты, меняет статусы проблем и проектов, правит любую карточку.
- **Владелец** — email указан в `СводПроекты.email владельца` хотя бы одного проекта; может редактировать только свои карточки, только разделы 2, 3, 4 (раздел 1 — автоматический; раздел 5 — требует статус `Выполнен`).

Проверка прав на запись:

```
canEdit(email, projectCode):
  role = Доступ.lookup(email)
  if role == 'coordinator': return true
  if role == 'owner' and СводПроекты[projectCode].email_владельца == email: return true
  return false
```

## 5. API Apps Script

Один URL, диспетчер по `action`. Ответ — `{ok: true, data: ...}` или `{ok: false, error: '...'}`.

### 5.1 Публичные (без токена)

| action | метод | назначение |
|---|---|---|
| `problems.list` | GET | Список проблем с фильтрами (`status`, `department`, `team`, `q`). |
| `problems.get` | GET | Полная проблема по индексу строки. |
| `projects.list` | GET | Список проектов (для карты и списков). |
| `projects.get` | GET | Полная карточка по коду `Пn-Кm`. |

### 5.2 Аутентификация

| action | метод | назначение |
|---|---|---|
| `auth.requestLink` | POST | Принимает `{email}`, шлёт magic-link если email в `Доступ`. Всегда `{ok: true}` (защита от перебора). Rate limit: 3 запроса на email / 10 минут. |
| `auth.activate` | GET | `?token=...` → помечает токен активированным, возвращает `{email, role, sessionToken, expiresAt}`. |
| `auth.whoami` | GET | По sessionToken возвращает `{email, role, ownedProjects}`. |

### 5.3 Запись (требуют sessionToken)

| action | метод | роли | назначение |
|---|---|---|---|
| `projects.create` | POST | coordinator | Создаёт проект из проблемы (см. раздел 8). |
| `projects.update` | POST | coordinator / owner | Правит ячейки карточки (разделы 2-5). |
| `projects.setStatus` | POST | coordinator | Меняет статус проекта. Для `Отменён` обязательна `причина`. |
| `problems.setStatus` | POST | coordinator | `Отменена` + `причина`, или возврат на `Парковка`. |

Все записи — внутри `LockService.getDocumentLock()`. Все двойные проверки прав (роль + владение).

## 7. Поток авторизации (magic link)

1. Пользователь открывает `login.html`, вводит email.
2. Фронт → `POST auth.requestLink {email}`.
3. Apps Script: если email в `Доступ` — создаёт токен (`истекает = now + 30 мин`, `использован = null`), отправляет через `MailApp.sendEmail` ссылку `https://.../auth.html?token=...`. Если не в `Доступ` — молча возвращает `ok: true`.
4. Пользователь кликает → `auth.html` → `GET auth.activate?token=...`.
5. Apps Script: валидирует, помечает `использован = now`, продлевает `истекает = now + 24 ч`, возвращает `{email, role, sessionToken}`.
6. Фронт сохраняет в `localStorage`, редиректит.
7. На каждой защищённой операции POST в теле передаётся `sessionToken`. Apps Script проверяет его по `Сессии`; при 401 фронт чистит localStorage и редиректит на `login.html`.

Очистка: ежедневный триггер удаляет из `Сессии` записи с `истекает < now - 7 дней`.

## 8. Поток создания проекта

### 8.1 Этап 1 — форма координатора (5 полей)

| Поле | Куда |
|---|---|
| Название проекта | `B17` карточки; автоматом в `D1`, `C62` через формулы |
| Владелец: ФИО | `C64` (выбор из `Служебный!R2:R18`) |
| Владелец: email | `СводПроекты.email владельца`, новая строка в `Доступ` с `роль = owner` |
| Тип проекта (S/M/L, радио) | `E30`; бюджет (`H30`) и длительность (`I30`) подтянутся формулами из `Служебный!J1:K3` |
| Месяц старта | Строка в `СводПроекты` (колонка `Месяц старта`); карточка берёт `C70` через VLOOKUP в `СводПроекты` |

Окончание и бюджет в форме не собираем — производные от типа.

### 8.2 Алгоритм `projects.create`

Внутри `LockService.getDocumentLock()`:

1. Вычислить `n` — сканируем имена листов по regex `/^П(\d+)-К4$/`, берём `max+1` или `1`.
2. Скопировать `_ШаблонКарточки.copyTo(spreadsheet)`, переименовать в `Пn-К4`.
3. Заполнить в новом листе:
   - `I2` = `Пn-К4`
   - `B7` = точное наименование проблемы из `БазаПроблем[row]`
   - `B17` = название
   - `E30` = тип
   - `C64` = ФИО владельца
4. Добавить строку в `СводПроекты`: код, название, тип, месяц старта, месяц окончания (= старт + `K1..K3` из `Служебный`), `email владельца`.
5. Добавить строку в `Карта2026`: код, статус `Не начат`, остальные поля — по формулам либо пусто.
6. Обновить строку в `БазаПроблем`: `Статус обработки = ОК`, `Проект = Пn-К4`, `ответственный = ФИО владельца`, `месяц старта`.
7. Если email владельца не в `Доступ` — добавить с ролью `owner`.
8. Применить защиту листа по эталону `П1-К1` (логика из существующей функции `copySheetProtectionToAllSheets`).
9. Вызвать `createDetailedProjectsReference()` — пересобрать `СправочникПроектов`.
10. `MailApp.sendEmail` владельцу — приветственное письмо с magic-link на `project.html?code=Пn-К4&edit=1`.
11. Вернуть `{code: "Пn-К4"}`; фронт редиректит координатора на карточку.

### 8.3 Этап 2 — доуточнение (опционально, в любой момент)

На `project.html` кнопка «Редактировать» по разделам. Владелец / координатор видят формы:

| Раздел | Поля для ручного ввода |
|---|---|
| 1. Проблема | — (полностью автоматически из `БазаПроблем`) |
| 2. Решение | `B17` (название), `B20` (описание), `B25` (метрика), `E28` (срок достижения) |
| 3. Калькулятор | `H36` (средняя ставка, dropdown), `E38`, `C40`, `E42`, `E43`, `C44`, `E46`, `E47`, `C48` (блоки А/Б/В/Г — суммы и описания) |
| 4. Паспорт | `B74:I78` (5 строк действий) |
| 5. Результаты | Только при `Карта2026.статус проекта = Выполнен`. Поля из раздела 5 шаблона. |

Владелец не видит поля, связанные со статусом проекта и бюджетом по месяцам — они только у координатора в `map.html` / отдельной форме смены статуса.
